# Интеллектуальный сервис планирования рабочих маршрутов инженеров

Кейс ЛЦТ 2026. Веб-сервис, который распределяет заявки между выездными инженерами
с учётом квалификации, оборудования, транспорта и временных окон, строит маршруты
с минимизацией времени в пути и нарушений SLA, автоматически перепланирует день
при новых событиях и объясняет каждое своё решение.

## Эффект на данных заказчика

Территория Восток, 17.08.2026: 66 заявок, 12 бригад. Базовый вариант — ровно по
ТЗ, п. 2.3: заявки по порядку поступления, каждая первому по порядку подходящему
инженеру, визиты в порядке назначения. Факт — как эти же заявки раскидал
настоящий диспетчер (контрольное распределение из выгрузки).

| Показатель | Сервис | Базовый по ТЗ | Факт диспетчера |
|---|---|---|---|
| **Закрыто в срок** | **66** | 52 | 63 |
| Назначено заявок | 66 | 52 | 64 |
| Задействовано исполнителей | **8** | 12 | 12 |
| Пробег, км | **251** | 379 | 282 |
| Время в пути, мин | 488 | 768 | 587 |
| Простой между визитами, мин | 17 | 3538 | 2472 |
| Нарушений SLA | 0 | 0 | 1 |

Против диспетчера: **на 11 % меньше километров, восемь бригад вместо
двенадцати и все 66 заявок вместо 64**. В выгрузке у диспетчера 4 просроченных
и 2 неотправленных. Против базового варианта ТЗ: минус 34 % пробега,
14 неназначенных против нуля.

Полный день с событиями — 6 отмен клиентов, невыход бригады, срочная авария:
**61 из 61 оставшихся заявок выполнено, ноль просрочек**, пять пересчётов по 3 с,
все с тёплым стартом от прошлого плана.

Остальные территории считаются тем же кодом (`compare_cli.py --snapshot …`).
Югоцентр: 56 из 56 семью бригадами вместо одиннадцати, 210 км против 262.
Юго-восток — половина заявок в Домодедове, Кашире и Ступине — считается по
областной дорожной выгрузке: 81 из 83, 76 в срок против 42 у воспроизведённого
факта, две заявки физически не влезают в окна.

## Стек

**Backend:** Python 3.11 · FastAPI · Google OR-Tools · scipy (граф OSM)
**Frontend:** React 18 · TypeScript · Vite · MapLibre GL JS — три зависимости
**Без Docker и без внешних API** — граф дорог и геокод в кеше, всё локально.

## Соответствие ТЗ

Что должно уметь решение (ТЗ, п. 2.1):

| # | Требование | Где |
|---|---|---|
| 1 | Загружать тестовые данные из CSV/JSON либо встроенный набор | Справочники → Данные: четыре встроенных, загрузка своих файлов |
| 2 | Распределять заявки между инженерами | OR-Tools, три обязательных ограничения + оборудование как усложнение |
| 3 | Порядок посещения адресов | маршрут по реальным дорогам с манёврами |
| 4 | Маршруты и точки на карте | Обзор дня и карточка инженера |
| 5 | Кто, куда и когда едет | лента дня и таблица визитов у каждого инженера |
| 6 | Перестроить план после события | срочная заявка, отмена, недоступность инженера — с пересчётом и списком изменений: перенесено, добавлено, снято, переставлено, сдвинуто по времени |
| 7 | Объяснить результат диспетчеру | карточка заявки: почему этот инженер, что было альтернативой; карточка инженера: почему маршрут такой — что диктовали ограничения, что выбрала оптимизация; «Не назначено»: причина по каждому в формулировках ТЗ |

Обязательные ограничения (п. 2.2): навык заявки входит в навыки инженера;
начало работы попадает в окно, работа с дорогой — в смену; при указанном типе
транспорта у инженера именно он. Обязательные метрики (п. 2.3) — число
задействованных исполнителей и пробег по каждому — стоят на экране «Эффект»
и входят в целевую функцию: за выход каждого инженера в поле начисляется
фиксированная плата.

## Быстрый старт

Собрать наборы данных (нужен только Python, без зависимостей). Выгрузка
заказчика уже лежит в `data/beeline/raw/`, кеш геокодера — рядом:

```bash
py -3.11 data/import_beeline.py
```

```bash
py -3.11 data/generate.py
```

Выгрузить дорожную сеть и метро из OpenStreetMap — один раз, дальше из кеша.
По умолчанию берётся Москва и юг области до Каширы (заявки заказчика на
Юго-востоке уходят туда); `--bbox moscow` — только Москва, вдвое легче:

```bash
py -3.11 data/fetch_osm.py
```

Без этого шага сервис поднимется, но время в пути будет считаться по прямой
с коэффициентом извилистости — грубее примерно в полтора раза, и на карте
вместо улиц будут прямые линии. В лог об этом пишется явно.

Поставить зависимости бэкенда и посчитать план дня:

```bash
py -3.11 -m venv backend/.venv && backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
```

```bash
cd backend && .venv/Scripts/python.exe solve_cli.py --time-limit 20 --limit 5
```

Полезные ключи `solve_cli.py`:

| Ключ | Что делает |
|---|---|
| `--preset staff \| sla \| travel \| balance` | что важнее: меньше персонала (метрика ТЗ), уложиться в SLA, экономить пробег или ровно загрузить людей |
| `--all-jobs` | планировать и те заявки, что поступают в течение дня |
| `--time-limit N` | секунд на поиск (10–20 достаточно) |
| `--limit N` | сколько маршрутов печатать |
| `--why` | разобрать, почему каждая неназначенная заявка не влезла |
| `--explain JOB-0011` | почему заявка досталась этому инженеру и в это время |

Сравнить с базовым вариантом ТЗ и с фактом диспетчера — та самая цифра эффекта:

```bash
cd backend && .venv/Scripts/python.exe compare_cli.py --time-limit 20
```

`--snapshot ../data/beeline/yugocentr/snapshot.json` — другая территория,
`--baseline smart` — вместо базового варианта ТЗ «грамотный диспетчер»
(по срочности окна ближайшему).

Прогнать тесты — они проверяют жёсткие ограничения плана, перепланирование
и граф маршрутизации:

```bash
cd backend && .venv/Scripts/python.exe -m pytest
```

Поднять API (документация и «поиграться» — на http://localhost:8000/docs):

```bash
cd backend && .venv/Scripts/python.exe -m uvicorn app.main:app --port 8000
```

Порядок вызовов для демонстрации: `POST /api/plan/build` → `GET /api/plan/compare`
→ `POST /api/plan/step` (промотать до ближайшего события и пересчитать) →
`GET /api/plan/explain/{job}` и `GET /api/plan/why-not`. Обновления плана
приходят в `ws://localhost:8000/ws`.

Диспетчерская (бэкенд должен быть уже запущен):

```bash
cd frontend && npm install && npm run dev
```

Откроется на http://localhost:5174. Запросы к `/api` и `/ws` проксируются на
бэкенд, так что CORS в деле не участвует.

## Что показывает интерфейс

- **Карта** — маршруты цветом по инженеру, номера визитов по порядку объезда,
  склады, неназначенные заявки красным кольцом. Клик по маршруту изолирует
  инженера, клик по точке открывает объяснение.
- **Гант** — визиты по инженерам на общей шкале дня. Полоска над визитом —
  окно клиента (плотная для жёсткого), штриховка — обед, красная рамка —
  нарушение SLA, белая обводка — то, что изменилось последним пересчётом.
  Синяя вертикаль — текущий момент дня.
- **Почему так** — разбор назначения: квалификация, оборудование, крюк
  относительно соседних визитов, и что было бы у каждой альтернативы.
- **Не назначено** — почему заявка не влезла, по каждому подходящему инженеру.
- **Эффект** — три столбца: сервис, базовый вариант по ТЗ, факт диспетчера
  заказчика; ниже — обязательные метрики ТЗ по каждому исполнителю.
- **Данные** (в Справочниках) — переключение между территориями заказчика и
  синтетикой, загрузка своего CSV/JSON, список допущений набора.
- **Отменить заявку / Вывести из смены** — кнопки на карточке заявки и на
  странице инженера: событие с текущего момента и немедленный пересчёт.
- **Проиграть день** — прогон событий подряд: видно, что новая аварийная заявка
  трогает 2–4 инженеров из 18, а не перекраивает город.
- **Новая заявка** — кнопка на экране «Заявки». Заказчик, тип работ, категория
  сложности, окно доступа, приоритет и точка объекта на карте; специализация,
  оборудование и норматив времени выводятся из справочников. После приёма
  сервис **сам пересчитывает остаток дня** — отдельной кнопки нет намеренно.
- **Завести инженера** — кнопка на экране «Инженеры». Квалификация, смена,
  обед, транспорт, оборудование и дом точкой на карте. Проверки приходят с
  человеческой формулировкой: габарит без машины не выдать, дом за пределами
  города не поставить. Новый инженер попадает в маршруты со следующего
  «Построить план» — интерфейс сообщает об этом баннером.
- **Передать другому инженеру** — кнопка у каждой альтернативы. Заявка
  закрепляется, план пересчитывается, и сразу показывается цена решения
  («+200 мин в пути»). Недопустимое закрепление отклоняется с причиной.
  Закреплённое солвер больше не трогает — на Ганте оно помечено пунктиром.

Прогнать рабочий день целиком — утренний план плюс перепланирование по событиям:

```bash
cd backend && .venv/Scripts/python.exe replan_cli.py --time-limit 3 --stability 200
```

`--stability N` — во сколько минут пути обходится перенос визита другому
инженеру. Чем больше, тем спокойнее план: при 200 срочная заявка на Востоке
трогает 2–3 бригады из 12, при 0 перекраивается половина территории.
